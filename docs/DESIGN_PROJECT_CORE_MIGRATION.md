# Remaining project core migration

Status: project-core ownership contract and migration exit checklist, following
the delivered semantic/desktop/panel batch on main597fee38. Release acceptance
requires the exact-candidate records and CI; this document does not certify a run
or claim that all twelve original architecture findings are closed.

## Facts and owners

Original source bytes, row domains, units and scientific provenance remain truth.
Scientific logical IDs and original locator strings are independent of the local
filesystem location. Managed documents own represented science/presentation;
Legacy/NativeSuite saved native bytes own their complete visual state. A native
cache, GUI draft, transport key or generation number cannot substitute for those
facts. Veusz remains the native renderer/editor adapter.

Retained operator versions own calculation and parameter admission, including
their actual immutable implementation closure. New versions are additive. A
legacy descriptor has an explicit retained implementation mapping; unknown or
missing versions refuse execution and cannot silently refresh the science.
Host grants separately admit external executor identity/action/source scope.
Model labels, hashes and project files do not create execution permission.

ProjectCommands owns normalized command admission, exact preview decisions,
effect preparation after admission and storage-only continuation. Discardable
private render/export/QA computation may precede that admission under the bounded
rule below; it has no durable exactly-once computation promise. FileProjectStore owns the
only durable command records, complete generations and authoritative project
head. Existing native/spec/manifest/delivery paths are verified materializations.
Semantic FileProjectRepository retains its validation and logical revision model;
when attached to a project its physical head/journal/CAS writes use the same
generation owner. A namespace backup is read-only evidence, never another head.

The source location port is explicit per request and resets on every exit.
Cold and pooled native requests bind the trusted selected project/generation and
finite resource roots. Stored specs, scientific source IDs and historical hashes
are not rewritten to make relocation work. Same-name files do not reconnect.

A known content-byte version travels through capture, table/text/sheet IO,
scientific audit, candidate preparation and publication archival. A directory or
semantic composite hash cannot stand in for one file's byte version. Recapture
checks the captured version and identity again; generic initial discovery does
not invent an expected hash. Physical delivery existence uses its selected host
resource capability, not an immutable scientific directory cache.

Initial request preparation captures the explicitly admitted original input as
well as generated scientific tables. Its original UUID/version facts are staged
in the same ProjectMutation. A ledger can select or check those captured facts;
it cannot grant access to a new path. Complete directory witnesses retain unused
members and empty directories. Native bindings carry original file byte versions
separately from directory/composite fingerprints, without changing the scientific
data-source projection merely to repair runtime IO.

NativeArtifactInput owns an exact document argument, invocation, physical identity,
mode and content hash. Registered documents can retain their preserved logical
locator; a private candidate keeps its artifact identity. Neither case turns it
into an immutable scientific source. Observing a human-saved Legacy document is
read-only: its semantic fingerprint binds the observed bytes, while the project
read witness retains the prior canonical version for a later audited
NativeAdoption. Default strict figure binding remains unchanged.

Explicit recovery of a missing rendered PDF, TIFF or PNG uses one typed
MissingGeneratedOutput declaration in the existing command. Its current complete
producer or fixed admitted catalog proves the output role and prior registered
version. Logical reads retain that prior version; physical absence is a separate
preimage checked at admission and commit. The new committed command may install
into exact absence, using exclusive creation and the bound parent identity.
Completed receipts never regain installation rights. This contract grants no
automatic repair of raw inputs, specs, native authority, QA/manifest/ZIP evidence,
immutable runs or unproven legacy aggregates.

Prepared template adoption carries a specific invocation-scoped baseline through
every AttachedProjectRepository storage batch, including early content interning
and attachment-index writes. The domain owner
project_lifecycle/prepared_admission.py validates that baseline under the
selected Store's short lock and supplies the complete current read set,
membership and original tree witnesses to the ordinary Core command. Standard
reservation and before-head validation therefore reject an intervening native,
source, mode or membership change before semantic publication. A postcheck alone
cannot establish this guarantee. Authorized final adoption selects the existing
request's complete delivery capability before capturing the attachment; invalid
checkpoints are rejected before creating that output. Read-only status does not
create delivery roots. The legacy no-Store path retains its existing exclusion
with both checks inside the lease.

A recorded source-root namespace composes preserved file locators; it does not
request a read of every file in that directory. Each actual file read retains
its own exact identity, byte version and alias checks. Conversely, observing a
complete directory requires its committed whole-tree witness, including original
membership and empty-directory facts; a list of file permissions cannot supply it.
Host-root identity and content freshness are separate observations. Recovery
locates the exact registered physical root before auditing the selected edited
native bytes; it cannot resolve that root through a materialized science cache.
Private staging basenames never become persistent logical run identities.

Source replacement admits its intent against the current canonical request and
physical preimage before reading a new worksheet, adopting native state or
allocating a candidate. Creation-time task context is not the current decision.
Public preview and direct preparation share that admission; a confirmed frozen
decision resumes through its existing exact read-set/CAS contract, rather than
being admitted again as a new request. Unknown current state does not imply an
unmapped project. Actual byte mismatches use typed boundary errors; permission,
membership, scope and unknown-state failures retain their own meanings.

Source-preview selector matches are only candidates, not exact byte versions.
Unknown execution with the same complete current read witness is queried before
new-source IO. The existing pure mapping-admission predicate separates new intent
from sealed-only continuation. An admitted new request retains native adoption
and observes its actual source/project/delivery versions before exact-key lookup;
an older preview cannot prohibit that new version. Without new admission, only an
unchanged sealed decision may replay. Both routes use one saved-witness verifier;
neither chooses the latest record nor repairs a stale decision.

Existing annotation admission precedes the mapping requirement after current
authority/preimage checks. It reads exact admitted specification bytes, or finite
project-local NoFollow legacy members, and never imports a store to reject a
request. Optional legacy figure directories are enumerated through the existing
project descriptor. A missing head is not an empty command history; rejection
must preserve that state rather than making an unsupported history query work.

A frozen source version is a read witness, not an automatic declaration that a
generated resource can never change again. Immutable input evidence requires an
explicit typed declaration, bound to the selected logical member, exact source
identity, byte version and the same command's read set and prepared bytes. The
generation's existing input-resource set owns that restriction. The same mutation
cannot also write that input; later output declarations cannot remove it.
Explicit source adoption retains its existing version-update contract. Ordinary
reads of older generated files must preserve their legitimate regeneration path.

Confirmed table mapping owns a finite immutable execution-input closure, including
its confirmation and lineage metadata. Creation and continuation must verify and
freeze that closure before publication, retaining original locators and numerical
contracts. An official offline bundle must retain the same verified inputs; a
missing original execution directory cannot be repaired by guessing a same-named
file. Compact read-only queries must not create source views to repeat numerical
mapping execution. When the selected evidence is explicitly sealed and full
revalidation requires that work, mapping verification is unknown; independent
raw/prepared-byte observations and artifact/QA status retain their own meaning.
Explicit export and refresh still perform the complete scientific validation.
The finite witness belongs to one operation, including its private workers; it
is neither a reusable validation result nor a grant for its parent directory.
Live inputs retain their exact fresh pre-commit checks. Explicit imported inputs
must instead prove their original complete committed byte/tree versions, without
claiming that an unavailable original host was observed again. Completion is the
authoritative head transition: later original-host changes cannot turn an already
committed publication into an uncommitted failure.

Read-only mapping evidence has these finite states; it never repairs admission:

| Selected state | Query contract |
| --- | --- |
| Current, completely registered inputs | Verify the exact selected versions and complete numerical mapping. |
| Older, partly registered inputs at their recorded live locations | Verify the complete mapping in one invocation-local witness. Report current facts without adding source identities or claiming historical authentication. |
| Official imported inputs with complete immutable proof | Inspect the exact sealed byte facts without materializing source views. Numerical mapping verification remains unknown until an explicit operation performs its complete replay. |
| Missing, changed or ambiguous required evidence | Preserve the existing refusal or unknown result; do not select another version or repair the project. |
| Undeclared or foreign reference | Refuse it within the existing selected-source boundary; a mapping fact never grants filesystem access. |

Unknown mapping evidence does not become readiness. Raw/prepared bytes, artifact
existence and QA remain independent observations; an actual edit or export keeps
its own complete scientific admission and validation.

Source-update review keeps the old selected generation and new private candidate
in separate version scopes. Each external review image uses the existing exact
native input/output roles; an image output grants no parent-directory write
authority. Compatible preserved styles come from the scientific correspondence
plan and share the ordinary audited setting executor. Public free-form editing
retains its own scientific restrictions. The update's physical raw/source
namespace requirements follow the selected before-members, while complete source
versions and scientific audits remain required even when no overlay exists.

Publication snapshots carry the already-verified file versions through their IO
boundary. They parse the resolved bytes with the existing numerical parser and
preserve original logical labels; an original locator is never rewritten to a
cache address. Source observations and output installation still belong to their
existing owners.

Terminal figure requests and stored source-artifact bindings retain their logical
source locators. A private candidate's physical input is used only at the IO
boundary; serializing that address into the scientific request would invalidate
continuation after cleanup. Mechanical and impact projections follow this same
rule as the existing rheology, DMA and DSC projections. Readers resolve the
selected source through the existing source-location port and retain any known
byte version. Physical native attestations continue to describe the bytes
actually observed. An active request census uses verified current members and
exact recorded storage roles; history objects are not additional active requests,
and an unknown file inside a storage directory is not silently ignored.

File projection also retires a direct leaf directory when this command deletes
all its old members and each has an exact produced-resource record, byte version,
size and mode. Current members, declared inputs, capability roots and unproved
directories prevent that inference. The same projection owner checks the current
head and directory identity, removes only the empty proved directory and can
finish after interruption without repeating the command effect. It does not scan
for empty directories or recursively clean unknown intermediate scaffolds. This
is a cooperative Store and descriptor contract, not OS isolation against a
hostile process racing the final filesystem operation.

## Command and failure rules

Native mutation preparation follows reserve, admitted applying, immutable candidate
seal, decision, complete generation, atomic head and verified materialization.
An unsealed uncertain execution never runs again automatically. A complete sealed
candidate has a durable accepted state before head publication and can finish
without executing the native edit again. Export-only continuation is separate
from applying the committed native/scientific effect.

An existing saved-project export enters that publication owner directly. It
audits and, when valid, explicitly adopts the exact current native bytes; it
cannot prepare a replacement from an older generation. Compact figure receipts
come from that committed publication's read/CAS snapshot, not an independently
read earlier registry. Selected suite export receipts overlay the immutable
creation baseline, preserving unselected figures and explicit empty exports.

Legacy native operations are read-only migration inputs. Import requires the
complete finite candidate/decision evidence and a new exact-current scientific
audit; mutable legacy files alone cannot authenticate historical execution or
authorize another native edit. Import a legacy pending operation at its original
verified locations before creating the official whole-project bundle. The new
typed outcome and its frozen evidence can then travel through normal bundle
continuation. Direct relocation of an unimported absolute-path legacy journal
is not claimed; ambiguous or incomplete evidence remains an explicit refusal.

Already captured semantic bytes use publish_prepared with a digest of the exact
writes, artifacts, result and prepared source versions. It has no native callback.
An interrupted prepared-storage seal may finish its original bytes; an interactive
preview cannot be accepted by that path.

Read-only queries do not repair or replace active native files. Resume validates
the original key, project and command binding before recovery. Invalid target
membership must fail before import, recovery or any other write.

The committed outcome also owns its materialization plan: installation generation,
parent and complete member set are derived from immutable reachable history.
Mutable receipt hints must match, and a later resource writer removes an older
receipt's right to reinstall its old preimage. Command filenames, keys and the
committed receipt census must agree before repair or new admission. A missing
committed receipt is an explicit recovery conflict, never a new command or an
instruction to recreate its effect.

A checked history is a derived validation result for one locked Store IO epoch,
not another state owner or a reusable pass. The complete immutable parent chain
is validated once within that batch; mutable receipt identity and membership,
sealed candidates, CAS and physical resource checks remain required. Metadata
writes and the end of the outer physical lease invalidate that result, including
descriptor reuse and nested operations. Installation separately obtains a fresh
last-writer decision; a read-only completed outcome cannot authorize old-byte
installation. No validation result survives into a later operation.

Executable deliveries are inspected through the selected materialized host
resource capability. A read-only scientific directory view cannot prove that a
user launcher is executable or that its delivery root owns this project. Logical
root/request/source identities remain distinct from their host IO locations;
content, executable mode, binding and exact package membership must still agree.
A finite file capability for a ZIP or source parent never grants whole-directory
enumeration. Cold continuation requires explicitly registered host locations,
not an old absolute path or a same-named foreign package.

Literal common/style edit checkpoints are intent resources, not execution
journals. Default entries inside an attached or recognized project use that same
Store; explicit external entries retain their independent request-file owner.
One entry lease keeps the selected project runtime through bound replay and owner
cleanup, including when the original project is offline. Rebinding physical host
locations does not rewrite the frozen intent or bypass namespace/source/output/
revision protections.

Private render/export/QA preparation may discover its output membership before
publication only when it changes no active/source/delivery files. This exception
does not admit external executor effects or GUI mutations. Existing records are
checked first; child shutdown and original wait precede any safe preparation retry.

Selected operations bind exact bytes plus fixed domain projections. Their typed
projected writes merge only the selected fields under the writer lease, retaining
unrelated current entries. Full resource writes retain exact CAS. Whole-set
operations also bind member names; additions cannot evade a read set containing
only previously existing files. There is no generic force flag or JSON patch.

One head switch cannot atomically replace files across separate roots. The durable
installation intent instead yields complete old state, complete new state, or
explicit recovery. Foreign bytes are preserved and block recovery. All trusted
roots share deterministic kernel lease ordering; finite ZIP capability never
scans an entire source/project parent. No power-loss or distributed-lock claim.
